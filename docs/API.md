# API Reference

Base URL: `http://<host>:8000/api/v1`

Interactive docs are also auto-generated by FastAPI at
`http://<host>:8000/docs` (Swagger UI) and `/redoc`.

> **Auth note:** dashboard-facing routes will require a staff JWT once
> the Auth/Dashboard feature is built (see `TODO(dashboard-auth)` markers
> in the route files). Right now these endpoints are unauthenticated —
> do not expose port 8000 directly to the internet; keep it behind your
> local network or a reverse proxy with its own access control until
> auth lands.

## Health

### `GET /health`

Returns service status. Used by Docker's healthcheck.

```json
{"status": "ok", "app": "GuildOS", "environment": "production"}
```

## Applications

### `POST /api/v1/applications`

Submit a new application. Called by the Discord bot's `/apply` flow;
triggers the AI evaluation synchronously.

Request:
```json
{
  "discord_id": 123456789012345678,
  "discord_username": "Steve#0001",
  "answers": {
    "ign": "SteveMC",
    "age": "22",
    "why_join": "Looking for an active community to play with"
  }
}
```

Response: `201 Created`, body is an `ApplicationOut` (see below).

### `GET /api/v1/applications`

List applications, most recent first.

Query params: `decision` (`pending`/`accepted`/`interview`/`declined`),
`limit` (default 50), `offset` (default 0).

### `GET /api/v1/applications/{id}`

Fetch a single application by ID. `404` if not found.

### `POST /api/v1/applications/{id}/decision`

Record the human staff decision. This is the only way an application's
`decision` field changes.

Request:
```json
{
  "decision": "accepted",
  "decided_by_discord_id": 987654321098765432,
  "staff_notes": "Great fit, welcomed by officer team."
}
```

### `ApplicationOut` shape

```json
{
  "id": 1,
  "member_id": 1,
  "answers": {"ign": "SteveMC", "...": "..."},
  "submitted_at": "2026-07-07T12:00:00Z",
  "decision": "pending",
  "decided_by_discord_id": null,
  "decided_at": null,
  "staff_notes": null,
  "ai_score": 82.0,
  "ai_activity_score": 90.0,
  "ai_maturity_score": 85.0,
  "ai_communication_score": 80.0,
  "ai_teamwork_score": 75.0,
  "ai_honesty_score": 88.0,
  "ai_toxicity_risk_score": 95.0,
  "ai_long_term_potential_score": 78.0,
  "ai_explanation": "Strong, consistent answers with good self-awareness.",
  "ai_positives": ["Plays 20+ hours/week", "Clear communicator"],
  "ai_concerns": ["Limited PvP experience"],
  "ai_recommendation": "accept",
  "ai_evaluated_at": "2026-07-07T12:00:05Z"
}
```

Note: `ai_toxicity_risk_score` follows a "higher is safer" convention
(100 = no risk detected, 0 = severe risk) so that every AI dimension
consistently means "higher is better" — see
`app/ai/recruitment_evaluator.py` for the reasoning.

## Members

### `GET /api/v1/members`

List members. Query params: `status`
(`applicant`/`active`/`inactive`/`staff`/`left`/`banned`), `limit`,
`offset`.

### `GET /api/v1/members/{id}`

Fetch a single member by ID. `404` if not found.
